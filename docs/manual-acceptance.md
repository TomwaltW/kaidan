# 人工验收清单（TΩ 之后，由总管在真实飞书环境执行）

这些检查需要真实的飞书应用与国产模型密钥，不属于任何 track 的自动验收。

## 准备
1. 飞书测试企业里创建企业自建应用，开启机器人能力；按 `deploy/README.md` 开通消息与多维表格相关权限；事件与卡片回调都选择"长连接"，订阅接收消息事件与卡片回调。
2. 用飞书官方轻量 CRM 模板建一个测试多维表格，录入 5–10 条虚构客户 / 商机 / 跟进；把应用添加为该多维表格的协作者（可编辑）。
3. 复制 `config/tenant.example.yaml` 与 `config/mapping.example.yaml`，填写 appToken、各表 tableId、字段名与测试用户的 open_id。
4. 设置环境变量 `KAIDAN_LLM_API_KEY`、`FEISHU_APP_ID`、`FEISHU_APP_SECRET`，运行 `pnpm kaidan serve --config config/<测试>.yaml`。

## 检查项（逐条打勾）
- [ ] 私聊机器人发送 `/晨报`：收到晨报卡片，页脚有"内容由 AI 生成 · 模型名"
- [ ] 私聊发送 `/会后 今天和 XX 开会，对方确认方案，下周三前给报价`：收到回复卡 + 审批卡，审批卡列出原值 → 新值
- [ ] 点"同意"：卡片变为"已写入 CRM"，多维表格里对应记录已更新；再点一次不会重复写
- [ ] 点"拒绝"：卡片变为"已拒绝"，多维表格无变化
- [ ] 在多维表格里先手动改同一字段，再点"同意"：提示"记录已被他人修改，请重新生成"
- [ ] 销售 A 询问销售 B 的商机：回复"无权限"，不泄露任何字段
- [ ] 群里不 @ 机器人发消息：机器人不响应；@ 机器人：正常响应
- [ ] 不在配置名单里的人私聊：收到"你还没有开通开单助手"
- [ ] 管理员发送 `/初始化`：收到 mapping.yaml 草稿，字段识别基本正确
- [ ] 把 `schedules.dailyBrief` 临时改成两分钟后，确认定时晨报送达
- [ ] 断网 30 秒再恢复：长连接自动重连，之后消息正常
- [ ] 用 `pnpm bench --config config/demo.mock.yaml` 跑一次评测，记录成功率、越权数（应为 0）、注入命中数（应为 0）、P95 延迟

## 试点前的非技术检查
- [ ] 与试点客户签委托处理协议（个人信息）与试点协议（范围、费用、退出条件）
- [ ] 咨询属地网信部门：本产品形态是否需要办理生成式 AI 应用登记
- [ ] 在配置里填写所用模型的备案号，确认卡片页脚公示正确
