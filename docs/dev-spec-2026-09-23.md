### R1 遗留 #5 · allowed_tools 拦截下沉到 ToolRegistry

**现状**

- `packages/agent/src/runtime.ts:80` `const allowed = new Set<string>(skill.allowedTools);`
- `packages/agent/src/runtime.ts:143-152`：`invokeTool` 在 agent 里就把越界调用挡掉，直接返回 `VALIDATION`「当前技能不允许调用工具 X」，**不进 registry → 不写 `tool_call` 审计**。注释自述原因：「registry 不知道技能边界」。
- `runtime.ts:153-158`：参数不是合法 JSON 同样在 agent 里挡掉、同样不审计。
- `packages/contracts/src/tools.ts:86-91` `ToolContext = { actor, traceId, now, skill? }` —— 只有技能名，没有边界。
- `packages/contracts/src/tools.ts:107-118` `ToolRegistry.invoke` 注释写明「每次调用写一条 audit tool_call」—— 与现状不一致（spec 2026-09-18 §3.3 同口径）。
- `packages/tools/src/index.ts:94-101`：registry 已在 `invoke` 末尾统一写 `tool_call`（`{tool, ok, ms, errorCode?}`），所以**只要调用进了 registry，审计就是全的**。

**契约变更**（`packages/contracts/src/tools.ts`）

```ts
export interface ToolContext {
  actor: Actor;
  traceId: string;
  now: Date;
  skill?: string;
  /** 本次调用所属技能的 allowed_tools；给了就由 registry 拦截越界调用（MCP 不给 = 不限技能边界） */
  allowedTools?: readonly ToolName[];
}
```

`ToolRegistry.invoke` 注释补两句：

- 「`ctx.allowedTools` 存在且不含 `name`（包括未知工具名）→ 返回 `VALIDATION`（`当前技能不允许调用工具 {name}`），照常写 `tool_call`（`errorCode: "VALIDATION"`）」；这一检查**先于**「未知工具」检查，模型侧文案因此与第 2 轮 agent 侧逐字一致
- 「`rawInput` 为 string 时先按 JSON 解析（空串视为 `{}`）；解析失败 → `VALIDATION`（`工具 {name} 的参数不是合法 JSON`），照常写 `tool_call`」

实现要点：agent 删掉 `allowed` 集合与 JSON 解析，把 `allowedTools: skill.allowedTools` 放进 ctx、把模型给的原始参数字符串原样交给 `registry.invoke`。MCP（`packages/mcp-server/src/server.ts:36`）不传 `allowedTools`，行为不变。

跨轨缺口（T2 注意）：agent 单测的替身 `packages/agent/test/fakes.ts:68-76` 的 `FakeRegistry.invoke` 不认 `allowedTools`、不解析字符串入参；`packages/agent/test/runtime.test.ts:122`、`:137` 两条断言的是第 2 轮「越界 / 非法 JSON 不进 registry」的旧行为。T2 要让替身按本节契约行事并改写这两条，否则 T2 自测全绿、合流才红。

### R3 `tool_choice`

**现状**

- `packages/contracts/src/agent.ts:27-33` `LlmRequest = { messages, tools?, temperature?, maxTokens?, signal? }`，**没有 tool_choice**。全仓 `grep -rn 'tool_choice\|toolChoice' packages apps --include=*.ts` → 0 命中。
- `packages/agent/src/openai-provider.ts:111-122` `buildBody` 只映射 `model / messages / tools / temperature / max_tokens`。
- 背景：`review/w2-run-2026-09-20.md` §6 第 1 条 ——「模型可以不调写入工具」是试点前头号问题；那里给了不动契约的补救追问方案，并注明更彻底的是加 `tool_choice`。**补救追问至今没实现**（`runtime.ts` 无相关逻辑）。

**契约变更**（`packages/contracts/src/agent.ts`）

```ts
export type LlmToolChoice = "auto" | "none" | "required" | { name: ToolName };
export interface LlmRequest {
  messages: LlmMessage[];
  tools?: LlmToolSpec[];
  /** 只在 tools 非空时下发；{name} 映射为 {type:"function",function:{name}} */
  toolChoice?: LlmToolChoice;
  temperature?: number;
  maxTokens?: number;
  signal?: AbortSignal;
}
```

实现要点（agent）：

- provider：`toolChoice` 映射到请求体 `tool_choice`；`tools` 为空时不下发。
- runtime 补救追问：技能 `allowedTools` 含 `propose_*`、本轮以 `final` 结束、提案数为 0、且回复里出现「提案 / 已更新 / 已生成 / 已记录」之一 → 追加一条 user 消息（「你还没有调用写入工具，现在只输出工具调用」）并带 `toolChoice` 再要一步；**最多一次**，计入 `maxSteps`。仍然没有提案 → 如实回复「这次没有生成提案」。
- scripted provider：`packages/agent/src/scripted.ts:54-60` 的 `copyRequest` 目前只拷 `messages / tools / temperature / maxTokens`，要补上 `toolChoice`（契约 `ScriptStep` 上方的注释已写明 requests 含 `toolChoice`），否则 b7 的 R3 用例永远看不到它（2026-09-23 在一次性副本上实测：T1 / T2 其余都做对、只漏这一处时，b7 的 R3a、R3b 两条红）。

## 5. 开锁 / 重新下锁的逐步顺序

> 守卫与钩子的判据都是**路径**。开锁要用户的一次明示授权：2026-09-23 用户授权总管代做第 3 步那一次 `mv`（只限 T0 worktree，主 checkout 与其它 worktree 照旧冻结），总管交由 T0 会话执行；其余轨的会话一律不开锁；全程不许 `--no-verify`。
> 钩子在 `.git/hooks/`，**所有 worktree 共用一份**。2026-09-21 已修：包装脚本改用 `git rev-parse --git-common-dir` 定位 `.mjs`（此前用 `--git-dir`，在 worktree 里会 `MODULE_NOT_FOUND`、把**所有**提交都拦掉；已在一次性仓库里验证修复后 worktree 内红 exit 1 / 绿 exit 0）。

1. **用户拍板**（已完成）。R1 / R2 / R4 / 开锁范围 / 切轨 2026-09-21 拍板；R3 / R5 / R6 2026-09-23 拍板（都选了草案默认值），赶在重新下锁之前。
2. **总管建 T0 worktree**，基线钉 main 当时的具体 sha：
   `git worktree add .worktrees/task-t0 -b t0-r3 <sha>`
3. **开锁（2026-09-23 用户授权总管代做，由 T0 会话执行，只在 T0 worktree 内）**：
   `cd <repo>/.worktrees/task-t0 && mv .contracts.lock .contracts.lock.off`
   此后该 worktree 里守卫与钩子都认为「没有锁」（两者都是锁不存在即放行）。**主 checkout 和其它 worktree 仍有锁、仍冻结。**
   去锁是整体的，但 T0 **只许写已拍板的开锁范围**（写进 T0 派单的白名单，TΩ 合流时按 `git diff --name-only` 逐条核对）：
   - `packages/contracts/**`
   - `config/**`
   - `docs/**`
   - `tests/e2e/**`（新建 `b7-round3.test.ts`；`harness.ts` 不改）
   - 根 `CLAUDE.md`（**只改**「本轮唯一权威文档」那一行）
   其余 frozen 条目（根 `README.md`、`.claude/**`、`package.json`、`pnpm-lock.yaml`、`pnpm-workspace.yaml`、`tsconfig.base.json`、`.nvmrc`、`.npmrc`、`.env.example`、`.gitignore`、各包 `package.json` / `tsconfig.json`）**一字不动**。
   核对命令：`git diff --name-only <T0 基线 sha> HEAD | grep -vE '^(packages/contracts/|config/|docs/|tests/e2e/|CLAUDE\.md$|\.contracts\.lock$)' > /tmp/k3-t0-out.txt; echo "OUT_OF_SCOPE_LINES=$(wc -l < /tmp/k3-t0-out.txt | tr -d ' ')"` → 期望 `0`（T0 若误改 `package.json`，这里就是 `1`）。放行 `.contracts.lock` 是因为第 6 步的重新下锁提交会改它，另按第 7 步单独核对它只改了 `round` 一行；这条是目录级粗筛，T0 派单另有逐文件的精确集合核对。
4. **T0 干活并提交**。只许 `git add <具体路径>`，**禁止 `git add -A` / `git add .`**（否则会把 `.contracts.lock` 的删除一起提交进去）。提交时钩子读不到锁 → 放行。
5. **改 round（2026-09-23 由 T0 会话代做，T0 worktree 内）**：在 `.contracts.lock.off` 里把 `"round": "2026-09-18"` 改成 `"2026-09-23"`（= 本文件日期）（`.contracts.lock.off` 不在 frozen 清单，编辑不会被拦）。**frozen 清单本身不变**：开锁范围里的 5 块（含本次追加的 `tests/e2e/**`、`CLAUDE.md`）在重新下锁后**照旧全部冻结**，追加的只是「本轮 T0 可写」，不是从清单里摘掉。
6. **重新下锁并提交（2026-09-23 由 T0 会话代做）**：
   ```bash
   cd <repo>/.worktrees/task-t0
   mv .contracts.lock.off .contracts.lock
   mv <repo>/.git/hooks/pre-commit <repo>/.git/hooks/pre-commit.off
   mv <repo>/.git/hooks/frozen-precommit.mjs <repo>/.git/hooks/frozen-precommit.mjs.off
   git commit -m "契约：第 3 轮重新下锁（round → 2026-09-23）" -- .contracts.lock
   mv <repo>/.git/hooks/pre-commit.off <repo>/.git/hooks/pre-commit
   mv <repo>/.git/hooks/frozen-precommit.mjs.off <repo>/.git/hooks/frozen-precommit.mjs
   test -x <repo>/.git/hooks/pre-commit; echo "EXECBIT_EXIT=$?"   # 期望 0
   ```
   钩子是共用的：关着的这几秒里**主 checkout 和其它 worktree 都不许提交**；关、提交、开在一次 Bash 调用里做完，提交失败也要先把钩子移回。关 / 开用 `mv`，不要 `rm`（钩子源码不进版本库，删了可能找不回）。
7. **核对锁**：`git diff <T0 基线 sha> -- .contracts.lock` 只有 `round` 一行变化（除非第 5 步明示改了 frozen 清单）；`git show HEAD:.contracts.lock` 能解析为 JSON。
8. **T0 合入 main**，再由总管按合入后的 main sha 建 T1、T2 worktree、落派单（TΩ 在两者合入后再建）。此后各 worktree 都带新锁，契约对它们冻结。
9. TΩ 合流后跑 §3 全量。
